## 一、当前结论

本次调试后，待复测版本采用以下链路：

```text
开始
→ 信息采集
→ 公式计算
→ 风险判断
→ 方案生成
→ 结果输出
→ 结束
```

其中：

1. **信息采集**：大模型节点，负责从用户自然语言里抽取购买信息。
2. **公式计算**：Python 代码节点，负责校验数据与计算覆盖天数。
3. **风险判断**：大模型 Text 输出，负责生成风险判断文本。
4. **方案生成**：大模型 Text 输出，负责生成三种方案文本。
5. **结果输出**：大模型 Text 输出，负责整理最终用户回复。
6. **结束节点**：返回结果输出节点的最终文本。

原来的“输入校验”节点已从主链路中移除，避免大模型 JSON 严格格式校验导致工作流中断。输入校验逻辑已合并到 Python 代码节点中。

---

## 二、为什么调整

调试中发现，讯飞星辰工作流对大模型节点的 JSON 输出校验非常严格。如果大模型输出出现以下情况，工作流会直接报错：

```text
Workflow engine protocol validation failed
Node set output content does not match format
```

实际遇到的问题包括：

1. Boolean 字段被模型输出为空字符串。
2. Array 字段被模型输出为 `[]`，但平台字段设置不匹配。
3. 大模型节点输出 JSON 多字段时容易出现字段为空、类型不一致、格式不完全匹配。
4. 未使用但留在画布上的节点也会被平台校验，导致“未连接的边”报错。

因此最终采用更稳定的方案：

```text
代码节点负责结构化计算和校验；
大模型节点只输出 Text 文本；
后续节点通过单字段文本传递结果。
```

---

## 三、最终链路配置

```text
开始 → 信息采集 → 公式计算 → 风险判断 → 方案生成 → 结果输出 → 结束
```

需要注意：

- 不再保留“输入校验”节点。
- 如果画布里仍有“输入校验”节点，必须删除，不能只断开连线。
- 节点 4、节点 5、节点 6 都不要设置为多字段 JSON 输出。
- 节点 4、节点 5、节点 6 全部使用 Text 单字段输出。

## 五、节点 2：公式计算

### 节点类型

```text

```

### 输入

```text
purchase_item：引用 → 信息采集 → purchase_item
price：引用 → 信息采集 → price
available_funds：引用 → 信息采集 → available_funds
avg_daily_spending：引用 → 信息采集 → avg_daily_spending
tracking_days：引用 → 信息采集 → tracking_days
substitute_item：引用 → 信息采集 → substitute_item
need_followup：引用 → 信息采集 → need_followup
followup_questions：引用 → 信息采集 → followup_questions
```

### 输出字段

只保留一个输出字段：

| 字段名 | 类型 | 说明 |
|---|---|---|
| calc_result | String | 公式计算结果，JSON 字符串，包含购买信息、校验结果、自由时间影响和覆盖天数变化 |

### Python 代码

```python
# -*- coding: utf-8 -*-
import json
import math


REQUIRED_FIELDS = {
    "price": "商品价格",
    "available_funds": "可支配资金",
    "avg_daily_spending": "平均日花销",
    "tracking_days": "记账天数"
}


def parse_positive_number(value):
    if value is None or str(value).strip() == "":
        return None, "missing"
    try:
        number = float(value)
    except Exception:
        return None, "invalid"
    if not math.isfinite(number) or number <= 0:
        return None, "invalid"
    return number, None


def round_half_up(value, digits=0):
    if value is None:
        return None
    factor = 10 ** digits
    rounded = math.floor(abs(value) * factor + 0.5) / factor
    return math.copysign(rounded, value)


def main(**kwargs):
    data = kwargs

    purchase_item = data.get("purchase_item", "")
    price = data.get("price", "")
    available_funds = data.get("available_funds", "")
    avg_daily_spending = data.get("avg_daily_spending", "")
    tracking_days = data.get("tracking_days", "")
    substitute_item = data.get("substitute_item", "")
    parsed = {}
    missing_fields = []
    invalid_fields = []
    for field_name in REQUIRED_FIELDS:
        number, error_type = parse_positive_number(data.get(field_name, ""))
        parsed[field_name] = number
        if error_type == "missing":
            missing_fields.append(field_name)
        elif error_type == "invalid":
            invalid_fields.append(field_name)

    if parsed["tracking_days"] is not None and not parsed["tracking_days"].is_integer():
        parsed["tracking_days"] = None
        invalid_fields.append("tracking_days")

    followup_items = []
    for field_name in missing_fields:
        followup_items.append("请补充%s" % REQUIRED_FIELDS[field_name])
    for field_name in invalid_fields:
        followup_items.append("请重新填写%s，需为大于0的%s" % (
            REQUIRED_FIELDS[field_name],
            "整数" if field_name == "tracking_days" else "数字"
        ))

    has_input_error = bool(missing_fields or invalid_fields)

    ret = {
        "purchase_item": purchase_item,
        "price": price,
        "available_funds": available_funds,
        "avg_daily_spending": avg_daily_spending,
        "tracking_days": tracking_days,
        "substitute_item": substitute_item,
        "flow_mode": "needs_input" if has_input_error else "normal",
        "missing_fields": missing_fields,
        "invalid_fields": invalid_fields,
        "followup_questions": "；".join(followup_items[:3]),
        "is_valid": not has_input_error,
        "funds_insufficient": False,
        "validation_message": "需要补充或修正数据" if has_input_error else "数据正常",
        "direct_cost_days": None,
        "before_coverage_days": None,
        "remaining_cash": None,
        "after_coverage_days": None,
        "coverage_change_days": None,
        "price_cash_ratio_pct": None,
        "sample_confidence": None,
        "lamp": None
    }

    if has_input_error:
        return {"calc_result": json.dumps(ret, ensure_ascii=False)}

    price_num = parsed["price"]
    available_funds_num = parsed["available_funds"]
    avg_daily_spending_num = parsed["avg_daily_spending"]
    tracking_days_num = int(parsed["tracking_days"])

    direct_cost_days_raw = price_num / avg_daily_spending_num
    before_coverage_days_raw = available_funds_num / avg_daily_spending_num
    remaining_cash = available_funds_num - price_num
    price_cash_ratio_raw = price_num / available_funds_num
    funds_insufficient = price_num > available_funds_num

    sample_confidence = (
        "low" if tracking_days_num < 30
        else "medium" if tracking_days_num < 100
        else "high"
    )

    ret.update({
        "flow_mode": "funds_insufficient" if funds_insufficient else "normal",
        "funds_insufficient": funds_insufficient,
        "validation_message": "当前可支配资金不足" if funds_insufficient else "数据正常",
        "direct_cost_days": int(round_half_up(direct_cost_days_raw)),
        "before_coverage_days": int(round_half_up(before_coverage_days_raw)),
        "remaining_cash": round_half_up(remaining_cash, 2),
        "price_cash_ratio_pct": round_half_up(price_cash_ratio_raw * 100, 1),
        "sample_confidence": sample_confidence
    })

    if funds_insufficient:
        ret["lamp"] = "red"
        return {"calc_result": json.dumps(ret, ensure_ascii=False)}

    after_coverage_days_raw = remaining_cash / avg_daily_spending_num
    coverage_change_days_raw = before_coverage_days_raw - after_coverage_days_raw

    if after_coverage_days_raw < 30 or price_cash_ratio_raw >= 0.5:
        lamp = "red"
    elif (
        after_coverage_days_raw < 90
        or price_cash_ratio_raw >= 0.2
        or tracking_days_num < 30
    ):
        lamp = "yellow"
    else:
        lamp = "green"

    ret.update({
        "after_coverage_days": int(round_half_up(after_coverage_days_raw)),
        "coverage_change_days": int(round_half_up(coverage_change_days_raw)),
        "lamp": lamp
    })

    return {
        "calc_result": json.dumps(ret, ensure_ascii=False)
    }
```

## 十一、最终调试经验

本次跑通的关键经验：

1. 用户不需要固定话术，但必须提供可计算所需的关键信息。
2. 关键在于固定信息量，用户话术无需固定。
3. 大模型多字段 JSON 输出在该平台上容易触发格式校验失败。
4. 代码节点更适合承担校验和计算。
5. 大模型节点后续尽量使用 Text 单字段输出，避免 Boolean、Array、多字段 JSON 的不稳定问题。
6. 没用的节点必须从画布删除，不能只断开连线。
