# 队员开工与回传清单

版本：v0.3

## 开始前

- [ ] 打开仓库并阅读 `00_请先阅读.md`。
- [ ] 阅读本目录 `README.md`、六份规格文件和 `07_v0.3证据型决策升级与队员反馈.md`。
- [ ] 阅读 `docs/superpowers/specs/2026-07-30-evidence-based-purchase-decision-agent-design.md`。
- [ ] 确认使用 v0.2 财务公式和灯号规则，并按 v0.3 增加独立决策状态。
- [ ] 在修改前运行 `git pull` 获取最新版本。
- [ ] 先回传平台能力核对和拟采用的节点图，再开始批量搭建。

## 搭建顺序

- [ ] 创建信息采集节点并映射五个必填字段。
- [ ] 创建安全边界和输入校验分支。
- [ ] 创建确定性公式计算节点。
- [ ] 创建样本可信度和灯号判断节点。
- [ ] 创建需求证据判断节点。
- [ ] 创建替代方案比较节点。
- [ ] 创建决策状态生成节点。
- [ ] 创建固定结构的结果输出节点。
- [ ] 创建选择记录与复盘节点，平台不支持持久化时生成可复制决策卡。
- [ ] 配置缺失字段、无效输入、资金不足和节点失败回路。

## 每个责任单元的回传内容

每完成一个责任单元，提交以下内容：

```text
节点名称：
完成时间：
输入变量：
输出变量：
条件分支：
实际运行结果：
平台限制或错误：
截图文件名：
本次修改的提交编号：
```

截图需隐藏账号信息、个人联系方式和真实财务数据。

## 测试回传

测试记录按 `05_测试用例与验收清单.md` 的顺序填写。每项需要包含输入、实际输出、预期差异、状态和截图。

状态只使用：

```text
未执行
通过
失败
阻塞
```

失败时记录实际数字和错误节点。阻塞时记录平台限制和需要项目负责人确认的问题。

## Git 协作

开始工作前运行：

```bash
git pull
```

每次只提交一个明确任务。例如：

```bash
git add 相关文件
git commit -m "完成输入校验节点"
git push
```

不得把账号密码、验证码、手机号、身份证号、真实账本或未打码截图提交到仓库。
