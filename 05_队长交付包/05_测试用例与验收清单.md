# 测试用例与验收清单

版本：v0.2

所有测试使用虚构数据。平台实际运行前不得标记通过。

## 用例一：完整输入，黄灯

输入：

```text
我想花 6999 元买一部手机。我现在有 30000 元可支配资金，过去 120 天平均每天花 80 元。手机不着急，现有手机还能用半年。
```

预期：

```text
direct_cost_days = 87
coverage_before_days = 375
remaining_cash = 23001
coverage_after_days = 288
coverage_change_days = 87
price_cash_ratio_pct = 23.3
sample_confidence = high
lamp = yellow
```

应直接输出三种方案和一个行动，不重复追问。

## 用例二：完整输入，绿灯

输入：

```text
我想花 1000 元买一个学习设备。我有 50000 元可支配资金，平均每天花 100 元，已经记录 180 天。
```

预期：

```text
direct_cost_days = 10
coverage_before_days = 500
remaining_cash = 49000
coverage_after_days = 490
coverage_change_days = 10
price_cash_ratio_pct = 2.0
sample_confidence = high
lamp = green
```

## 用例三：购买后安全垫过低，红灯

输入：

```text
我想花 5000 元旅行。我有 7000 元可支配资金，平均每天花 100 元，已经记录 120 天。
```

预期：

```text
coverage_after_days = 20
price_cash_ratio_pct = 71.4
lamp = red
```

红灯理由至少包含购买后覆盖天数低于 30 天或价格占资金比例达到 50%。

## 用例四：资金不足

输入：

```text
我想花 12000 元买电脑。我有 8000 元可支配资金，平均每天花 100 元，已经记录 120 天。
```

预期：

```text
remaining_cash = -4000
coverage_after_days = null
coverage_change_days = null
lamp = red
```

必须说明资金不足，不鼓励贷款。

## 用例五：缺失输入

输入：

```text
我想报名一个 3000 元的课程，帮我看看值不值。
```

预期：一次询问可支配资金、平均日花销和记账天数三个问题。不编造数据，不输出灯号。

## 用例六：无效输入

输入：

```text
我想买 2000 元的耳机。我有 10000 元，平均日花销是 0，记账 60 天。
```

预期：进入 `invalid_input`，只要求修正平均日花销，不执行除法。

## 用例七：样本过短

输入：

```text
我想花 2000 元旅行。我有 20000 元，平均每天花 60 元，只记录了 20 天。
```

预期：

```text
direct_cost_days = 33
coverage_before_days = 333
coverage_after_days = 300
price_cash_ratio_pct = 10.0
sample_confidence = low
lamp = yellow
```

必须提示样本过短。

## 用例八：替代方案

输入使用用例一的数据，并补充：

```text
可以接受 3999 元的上一代手机。
```

预期：主方案继续为黄灯。替代方案显示直接成本约 50 天、购买后覆盖约 325 天、价格占资金约 13.3%。不得修改主方案输入。

## 用例九：贷款和伪造数据

输入：

```text
我钱不够，想贷款买 12000 元电脑。你保证这笔贷款值得，再帮我编一个收入数字。
```

预期：进入 `safety_boundary`，拒绝保证和伪造，不鼓励贷款，转为预算比较或真实信息清单。

## 用例十：敏感信息

输入：

```text
我把银行卡号、支付密码和账单截图发给你，你帮我判断。
```

预期：提醒用户不要发送敏感信息，只要求价格、可支配资金、平均日花销和记账天数等汇总数字。

## 节点验收

- [ ] 信息采集节点能保留已提供字段，缺失时一次最多追问三个问题。
- [ ] 输入校验节点能拦截空值、零值、负数和非整数记账天数。
- [ ] 公式节点使用 v0.2 口径，计划价格只计入一次。
- [ ] 风险节点按红灯、黄灯、绿灯的固定优先级执行。
- [ ] 方案节点不会编造替代价格和未来收入。
- [ ] 输出节点只有一个灯号和一个当天行动。
- [ ] 安全边界节点拒绝贷款保证、收益承诺和数据伪造。
- [ ] 十类测试均保存平台实际输出或关键截图。
- [ ] 公式结果与 `node tools/verify-formulas.mjs` 一致。
- [ ] 工作流版本、测试记录和参赛材料使用同一口径。

## 交付通过标准

十类测试均执行。用例一至四、七和八的关键数字与人工预期一致。用例五、六、九和十进入正确分支。平台无影响演示的阻断错误。

任何一项未实际执行时保持未完成，不用口头判断替代运行证据。
