# v0.3 证据型决策升级与队员反馈

版本：v0.3

日期：2026-07-30

状态：产品设计已确认，等待工作流负责人评审和搭建

## 先读什么

先阅读正式设计稿：

`docs/superpowers/specs/2026-07-30-evidence-based-purchase-decision-agent-design.md`

再阅读本目录的 v0.2 字段、公式、节点、提示词和测试文件。v0.2 继续作为财务计算基线，v0.3 负责新增需求证据、替代证据、决策状态和复盘闭环。

## 本次变化

现有红黄绿灯继续只表示现金安全垫影响。

新增需求证据状态、替代证据状态和决策状态。购买原因、设备问题、影响频率、购买期限、预期使用频率和替代方案需要进入工作流判断。

最终工作流从六个责任单元扩展为八个责任单元，增加需求证据判断、选择记录与复盘。替代方案比较从固定文案升级为独立责任单元。

## 队长已经确定的内容

目标用户、首版场景、财务公式、安全边界、三种决策状态、主案例、结果结构和用户验证标准已经确定。

下列内容不得直接修改：

1. v0.2 财务公式和灯号含义。
2. `ready_to_consider`、`gather_evidence`、`lower_budget_or_alternative` 三种决策状态的基本含义。
3. 不鼓励贷款、不预测收益、不采集敏感信息的边界。
4. 作品只提供消费决策辅助，最终决定由用户作出。

发现问题时记录原因和替代建议，由两人确认后更新规格。

## 队员可以直接决定的内容

工作流负责人可以根据星辰平台实际能力决定：

1. 八个责任单元对应多少个平台节点。
2. 字段使用对象、字符串还是平台变量保存。
3. 需求证据判断放在条件节点、代码节点或大模型节点。
4. 提示词如何拆分到不同节点。
5. 平台无法持久化时，决策卡怎样生成和回传。
6. 节点名称、画布布局和调试顺序。

每项决定需要在回传中说明原因、平台限制和测试证据。

## 队员第一轮任务

先完成平台能力核对，不批量搭建。

需要确认：

1. 是否支持结构化对象和数组变量。
2. 是否支持确定性计算或代码节点。
3. 是否支持条件分支和空值处理。
4. 是否支持会话内保存字段。
5. 是否支持跨会话持久化或定时触发。
6. 是否可以导出或复制决策卡。

第一轮回传包括平台能力表、拟采用的节点图、变量映射和一个最小可运行案例。

## 最小可运行案例

使用虚构数据：

```text
我想花 6999 元购买笔记本电脑。
可支配资金 30000 元，平均日花销 80 元，记账 120 天。
旧电脑还能使用，只是偶尔卡顿。
```

预期财务灯号为黄灯。

由于问题频率、受阻任务、购买期限和替代方案不足，需求证据与替代证据均不充分，决策状态为 `gather_evidence`。

当天行动为记录 7 天卡顿次数和受影响任务。

## 不同点子反馈

工作流负责人可以补充与当前设计不同的想法，但需要回答：

1. 想解决的具体问题是什么。
2. 与当前方案相比会改变哪个决策结果。
3. 平台能否在比赛时间内完成。
4. 需要新增哪些数据。
5. 如何验证这个想法有效。
6. 会不会扩大隐私或金融建议风险。

点子先作为建议记录，不直接改变已确认口径。
