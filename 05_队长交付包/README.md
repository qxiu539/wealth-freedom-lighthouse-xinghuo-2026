# 财富自由指南灯队长交付包

版本：v0.2 财务基线，v0.3 证据型决策升级

日期：2026-07-30

状态：v0.3 产品设计已确认，等待工作流负责人评审平台能力

## 交付目的

本目录把产品规则转换成可以直接搭建工作流的规格。工作流负责人无需重新确定产品口径，只需按字段、公式、节点、提示词和测试用例完成平台配置，并回传实际结果。

## 文件入口

`01_字段与变量字典.md` 定义用户输入、内部变量、节点输出和缺失字段处理规则。

`02_公式与灯号规则.md` 定义 v0.2 的唯一计算口径、风险优先级、灯号阈值和四舍五入规则。

`03_工作流节点说明.md` 定义 v0.2 六个责任单元的输入、处理、输出、异常分支和完成标志。

`04_提示词与输出模板.md` 提供信息采集、方案生成和最终输出节点可直接使用的提示词。

`05_测试用例与验收清单.md` 提供十类测试、人工预期和交付验收条件。

`06_队员开工与回传清单.md` 说明队员开始搭建、提交结果和记录问题时需要做什么。

`07_v0.3证据型决策升级与队员反馈.md` 说明新增战略、分工边界、平台能力核对和不同点子反馈方式。

正式设计稿位于 `docs/superpowers/specs/2026-07-30-evidence-based-purchase-decision-agent-design.md`。

仓库根目录的 `tools/verify-formulas.mjs` 用虚构数据验证公式和灯号规则。运行 `node tools/verify-formulas.mjs`，看到全部测试通过即表示本地规则一致。

## 版本口径

v0.2 将计划价格从可支配资金中扣除后，继续使用原平均日花销计算购买后覆盖天数。计划价格只计入一次。

旧版指令型 Demo 曾把计划价格同时加入日均花销分母并从资金中扣除，适合保留为历史测试记录，不再作为工作流版本的验收口径。

工作流负责人如果发现平台限制或公式实现问题，先记录问题和截图，不自行修改阈值、字段含义或输出承诺。项目负责人确认后再更新本目录的版本。
