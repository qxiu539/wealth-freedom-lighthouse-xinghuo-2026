# 字段与变量字典

版本：v0.2

## 必填输入

| 字段 | 类型 | 示例 | 校验规则 | 用途 |
|---|---|---:|---|---|
| `purchase_name` | 文本 | 手机 | 去除首尾空格后不能为空 | 展示购买内容 |
| `price` | 数字 | 6999 | 必须大于 0，单位为元 | 计算直接成本和资金变化 |
| `available_cash` | 数字 | 30000 | 必须大于 0，单位为元 | 计算购买前后覆盖天数 |
| `avg_daily_expense` | 数字 | 80 | 必须大于 0，单位为元每天 | 自由天数换算基准 |
| `tracking_days` | 整数 | 120 | 必须大于 0，单位为天 | 判断样本可信度 |

## 可选输入

| 字段 | 类型 | 允许值或示例 | 缺失处理 |
|---|---|---|---|
| `purchase_reason` | 文本 | 现有手机还能用半年 | 不影响计算 |
| `urgency` | 枚举 | `urgent`、`within_30_days`、`not_urgent` | 记为 `unknown` |
| `need_level` | 枚举 | `essential`、`improves_life`、`optional` | 记为 `unknown` |
| `alternative_price` | 数字 | 3999 | 缺失时只提示用户补充，不编造 |
| `alternative_name` | 文本 | 上一代手机 | 缺失时显示“待补充替代方案” |

可选字段用于解释和方案比较，不得改变确定性公式。紧急程度和需要程度可以影响建议文字，不能覆盖资金不足或安全垫过低的红灯规则。

## 内部计算变量

| 字段 | 类型 | 计算或来源 |
|---|---|---|
| `direct_cost_days_raw` | 数字 | `price / avg_daily_expense` |
| `coverage_before_days_raw` | 数字 | `available_cash / avg_daily_expense` |
| `remaining_cash` | 数字 | `available_cash - price` |
| `coverage_after_days_raw` | 数字或空值 | 资金充足时为 `remaining_cash / avg_daily_expense` |
| `coverage_change_days_raw` | 数字或空值 | `coverage_before_days_raw - coverage_after_days_raw` |
| `price_cash_ratio_raw` | 数字 | `price / available_cash` |
| `direct_cost_days` | 整数 | 原始值四舍五入 |
| `coverage_before_days` | 整数 | 原始值四舍五入 |
| `coverage_after_days` | 整数或空值 | 原始值四舍五入 |
| `coverage_change_days` | 整数或空值 | 原始值四舍五入 |
| `price_cash_ratio_pct` | 数字 | 百分比保留 1 位小数 |
| `sample_confidence` | 枚举 | `low`、`medium`、`high` |
| `lamp` | 枚举 | `green`、`yellow`、`red` |
| `flow_mode` | 枚举 | `normal`、`need_input`、`invalid_input`、`safety_boundary` |

## 缺失字段处理

一次最多追问三个必填字段。追问优先级固定为：

1. `available_cash`
2. `avg_daily_expense`
3. `tracking_days`
4. `price`
5. `purchase_name`

已明确提供的字段不得重复询问。必填字段补齐前，工作流不得生成计算结果和灯号。

## 禁止采集字段

不得采集银行卡号、身份证号、支付密码、验证码、账单截图、精确住址、账号密码或完整真实账本。用户主动发送时，提醒其删除或打码，并只保留完成本次计算需要的汇总数字。
