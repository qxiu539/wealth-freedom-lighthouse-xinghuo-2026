# 工作流节点说明

版本：v0.2

## 总体流程

```text
开始
  → 信息采集
  → 安全边界检查
  → 必填字段检查
  → 输入校验
  → 确定性公式计算
  → 风险与灯号判断
  → 三种方案生成
  → 结果输出
  → 结束
```

平台允许时，必填字段检查和输入校验可以放在同一责任单元中。公式计算必须使用确定性计算节点或等价表达式，不交给大模型自由心算。

## 节点一：信息采集

输入：用户自然语言。

处理：提取 `purchase_name`、`price`、`available_cash`、`avg_daily_expense`、`tracking_days` 和可选字段。

输出：字段对象、缺失字段列表、用户原始意图摘要。

异常分支：无法确认数值单位时先追问。一次最多追问三个必填字段。

完成标志：五个必填字段均有明确值，或进入 `need_input` 分支。

## 节点二：安全边界与输入校验

输入：信息采集节点的字段对象。

处理：

1. 检查是否要求贷款保证、收益承诺、伪造数据或提交敏感信息。
2. 检查文本字段是否为空。
3. 检查 `price`、`available_cash`、`avg_daily_expense` 和 `tracking_days` 是否大于 0。
4. 检查 `tracking_days` 是否为整数。

输出：`flow_mode`、校验结果、需要修正的字段和提示语。

异常分支：

`safety_boundary` 直接进入边界输出。

`need_input` 或 `invalid_input` 返回信息采集节点。

完成标志：`flow_mode = normal`。

## 节点三：确定性公式计算

输入：通过校验的五个必填字段和可选替代价格。

处理：严格执行 `02_公式与灯号规则.md`。

输出：原始计算值、展示值、剩余资金和价格占比。

异常分支：价格高于可支配资金时，购买后覆盖天数和变化量输出空值，不执行除法。

完成标志：所有适用字段均有数值，人工复算一致。

## 节点四：风险与灯号判断

输入：原始输入和计算节点输出。

处理：

1. 判断样本可信度。
2. 按红灯条件逐项判断。
3. 未触发红灯时按黄灯条件逐项判断。
4. 记录触发条件和警告。

输出：`sample_confidence`、`lamp`、`reasons` 和 `warnings`。

完成标志：灯号只有一个，理由可以从结构化数据回查。

## 节点五：三种方案生成

输入：用户目的、可选字段、计算结果、灯号和风险理由。

处理：

现在购买：说明直接成本、剩余资金、购买后覆盖天数和主要风险。

延后 30 天：说明等待期可以用于补充需求证据、比较价格或增加资金。没有未来收入数据时，不预测 30 天后的金额。

降低预算或替代：有 `alternative_price` 时执行确定性计算；缺失时提示用户补充预算上限或替代价格。

输出：三个方案的结构化摘要。

异常分支：不得编造替代品价格、未来收入、投资收益或商品质量。

完成标志：三种方案均出现，未知数据明确标记待补充。

## 节点六：结果输出

输入：全部结构化结果。

处理：按 `04_提示词与输出模板.md` 生成用户可读结果。

输出顺序固定为：

1. 你的计划
2. 自由时间影响
3. 三种选择
4. 指南灯建议
5. 今天的一个动作

完成标志：公式数字一致、只有一个灯号、只有一个当天行动、不替用户做最终决定。

## 建议的异常回路

缺少字段或字段无效时，回到信息采集节点，不清空用户已经提供的有效字段。

平台节点失败时，输出可识别的错误状态和节点名称，避免继续生成看似完整的结果。

建议错误字段：

```json
{
  "flow_mode": "invalid_input",
  "error_node": "validation",
  "error_code": "AVG_DAILY_EXPENSE_NON_POSITIVE",
  "message": "平均日花销需要大于 0，请重新输入。"
}
```

## 平台搭建回传要求

工作流负责人每完成一个责任单元，回传节点截图、变量映射和一次有效运行结果。

平台字段或节点能力与本说明不一致时，记录平台限制、当前替代方案和影响，不直接更改产品口径。
