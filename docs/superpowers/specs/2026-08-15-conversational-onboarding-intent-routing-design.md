# 财富自由指南灯入口说明与对话分流设计

## 设计结论

财富自由指南灯继续聚焦大学生大额消费前决策，不扩展为综合理财、投资或资产配置助手。

本次调整解决一项已经确认的问题和一项需要测试验证的风险。已经确认的问题是名称容易让首次用户误解为理财助手。根据现有固定输入和输出结构推断，一般理财问题、口语化输入和结果追问存在进入不合适字段采集或固定结果模板的风险；由于未取得本次反馈对应的原始输入和完整回答，该风险不能写成已经复现的故障。

正式版保留现有确定性财务公式、灯号阈值、需求证据、替代证据和决策状态。新增页面定位说明、意图识别、渐进式追问和按场景表达，让用户无需掌握提示词格式也能完成一次分析。

## 当前基线

截至 2026-08-03，讯飞星辰 Agent 平台上的 v0.3 基础工作流采用五个实际节点：

```text
开始 → 信息采集 → 确定性决策核心 → 结果输出 → 结束
```

其中，大模型承担自然语言信息提取和中文表达；财务公式、财务灯号、需求证据、替代证据、决策状态和安全边界由确定性核心处理。

项目记录显示，完整输入、缺失输入、财务红灯、安全边界和证据已齐五类平台用例已经通过，本地六项公式校验通过。当前测试尚未覆盖一般理财提问、连续多轮补充、只解释结果和修改单个输入后的局部重算。现有仓库记录了节点职责和测试结果，但没有保存一份可以直接回放的 v0.3 平台节点完整导出；实施前仍需从平台核对当前提示词、代码和变量映射。

## 问题定义

### 定位误解

名称中的“财富自由”容易让用户预期获得理财教学、资金分配、投资或资产规划服务。作品当前能力集中在一笔具体大额消费的财务影响、需求证据和替代方案分析。页面若未直接说明边界，用户可能从一般理财问题开始对话。

### 输入门槛

现有分析至少需要购买内容、价格、可支配资金、平均日花销和记账天数。需求证据和替代方案还需要当前问题、影响频率、受阻任务、购买期限、预计使用频率、当前解决方案及替代方案信息。

首次用户通常无法一次提供全部信息，也不应被要求记忆字段名称或固定格式。

### 回复格式过硬

完整决策卡适合完成计算后的交付。一般理财问题、信息不足和结果追问若继续输出固定决策卡，会增加答非所问和程序化表达的感觉。

## 目标与成功标准

本次调整的目标是让首次用户理解作品用途，并在自然对话中进入正确分支。

成功标准如下：

1. 首次用户能在十秒内识别作品主要分析一笔具体的大额消费。
2. 用户不需要了解字段名或编写固定格式提示词。
3. 一般理财问题不会触发财务灯号、决策状态或五个必填字段的集中追问。
4. 信息不足时，系统能复述已知信息，每轮只追问一到两个最关键问题，并保留同一会话中已经确认的数据。
5. 五个财务必填字段满足最低可计算条件时，先输出一句核心判断，再展示可复算的详细决策卡。
6. 用户追问某个结果时，只回答当前问题；输入数字发生变化时，只重新计算受影响的结果，并说明变化。
7. 现有公式、灯号和安全边界继续成立；缺失输入用例按新的每轮最多两个问题更新预期后通过。

## 产品边界

本次调整包含：

1. 页面副标题、简介、欢迎语和开场问题。
2. 信息采集节点中的意图识别、字段提取和会话内已知信息保留规则。
3. 结果输出节点中的分支表达和局部追问规则。
4. 新增对话类测试和回归测试。

本次调整不包含：

1. 投资建议、资产配置、借贷建议、收益预测、税务或法律建议。
2. 银行账单导入、完整预算管理、全网比价或商品质量评价。
3. 修改财务公式、灯号阈值、需求证据规则、替代证据规则或三种决策状态含义。
4. 新增外部付费接口、账号连接或敏感个人数据采集。
5. 在平台能力尚未验证时承诺跨会话长期记忆。

## 页面入口设计

### 名称与副标题

作品名称继续使用“财富自由指南灯”。页面能够配置副标题时，使用“大额消费决策助手”。平台没有独立副标题字段时，将该定位放在简介首句。

### 页面简介与欢迎语

```text
财富自由指南灯｜大额消费决策助手

我可以帮你判断一笔大额消费会占用多少自由天数，并结合现金安全垫、实际需求和替代方案，分析现在购买、延后观察或降低预算哪种选择更合适。

你可以提供：
1. 准备购买什么，大概多少钱
2. 当前可支配资金
3. 平均每天花多少钱，已经记录了多久
4. 为什么想买，目前遇到了什么问题
5. 是否考虑过维修、继续使用或其他价位方案

不需要记住固定格式，也不需要一次写完整。你可以先说购买内容和价格，我会逐步询问缺少的信息。

本工具主要提供大额消费决策辅助，不提供投资、借贷或收益建议。
```

### 开场问题

1. 我想买一台 6999 元的电脑，应该怎么判断？
2. 我想报名一个 3000 元的课程，帮我分析一下。
3. 我不知道需要提供什么信息，请一步一步问我。

## 对话意图与数据流

信息采集节点需要先判断当前输入属于哪一种模式，再决定是否提取和校验消费字段。

分支优先级固定为：安全边界、无效或冲突输入、结果追问、具体消费计划、一般理财问题或意图不明确。高优先级状态命中后，不再同时输出低优先级分支内容。一般性的投资知识提问只进入能力范围说明；只有贷款保证、收益承诺、数据伪造或敏感信息等明确风险请求才进入安全边界。没有具体消费且意图不明确时使用 `scope_guidance`，简要介绍能力并邀请用户选择整体资金问题或具体消费分析。

### 模式一：一般理财问题

适用输入包括“怎么理财”“怎样实现财富自由”“钱应该怎么分配”等未指向具体消费计划的问题，也包括“你好”“你能做什么”等没有具体消费信息的模糊开场。

建议内部状态为 `scope_guidance`。

回复只需要：

1. 一般理财问题用一句话确认用户想了解整体资金安排；模糊开场直接说明当前能力。
2. 说明当前作品擅长分析一笔具体大额消费。
3. 邀请用户先提供购买内容和大概价格。

此模式不得要求用户一次提供五个财务字段，不得输出财务灯号、需求证据或决策状态。

参考回复：

```text
听起来你想了解整体资金安排。财富自由指南灯目前主要帮助你判断一笔具体的大额消费，例如电脑、课程、旅行或游戏充值。如果你最近正在考虑一笔消费，可以先告诉我买什么和大概价格，其他信息我会逐步询问。
```

### 模式二：消费信息不足

适用输入是已经出现具体消费意图，但缺少必填字段或存在单位歧义。

建议沿用 `need_input` 状态，并增加 `known_fields` 和 `missing_fields`。

回复顺序为：

1. 用一句话复述已经确认的购买内容和价格。
2. 每轮只询问一到两个最关键的缺失项。
3. 不重复询问同一会话中已经确认的字段。

追问优先级继续沿用现有规则，但每轮追问数量从最多三个调整为最多两个：可支配资金、平均日花销、记账天数、价格、购买内容。

需求证据和替代方案字段随用户表达同步提取。五个财务必填字段补齐后即可生成财务分析，不能因为需求证据或替代证据不足而强制进行多轮问答。缺失证据进入 `gather_evidence` 和当天行动；只有用户要求进一步判断购买必要性时，才继续询问一个最有价值的证据问题。

### 模式三：达到最低可计算条件

五个财务必填字段通过校验后，进入确定性决策核心。核心继续输出财务计算、财务灯号、需求证据、替代证据、决策状态、理由和当天行动。

结果输出节点先给一句核心判断，再展示详细决策卡。核心判断必须同时区分财务灯号和决策状态，避免把财务承受力解释成商品价值结论。

参考结构：

```text
核心判断：从现金安全垫看，这笔消费处于黄灯范围；目前支持购买必要性的证据还不充分，建议先完成一次取证行动。

一、你的计划与计算假设
二、自由时间和现金安全垫影响
三、需求证据与缺失项
四、主方案与替代方案
五、财务灯号和决策状态
六、今天的一个动作与复盘方式
```

### 模式四：结果追问

适用输入包括“黄灯是什么意思”“为什么要等七天”“如果预算改成 5000 元呢”等针对本轮结果的继续提问。

建议内部状态为 `follow_up`。

处理规则如下：

1. 解释性问题只解释被问到的概念或依据。
2. 用户明确更正价格、资金或日均花销时，更新对应已确认字段；用户提出“如果价格变成 5000 元”等假设时，将新值写入 `scenario_overrides`，不覆盖原方案。
3. 回复只展示发生变化的数字、灯号、决策状态和原因。
4. 用户要求完整报告时，再重新输出完整决策卡。
5. 会话上下文不足时，明确列出需要重新确认的字段，不使用猜测值补齐。

### 模式五：安全边界

现有 `safety_boundary` 继续保留最高处理优先级。

用户要求贷款保证、收益承诺、伪造数据，或发送账号凭据和敏感信息时，直接进入安全边界。此状态只输出边界说明和一个安全的下一步，不执行财务计算。

### 模式六：无效或冲突输入

现有 `invalid_input` 继续保留。数字为空、非数字、小于等于零或单位无法确认时，进入无效输入或信息补充流程。新输入与已经确认的字段冲突且用户没有明确表达更正或假设条件时，先请用户确认采用哪个值。用户明确说“价格其实是 5999 元”时直接按更正处理；用户说“如果价格降到 5000 元”时按结果追问和假设重算处理。此状态不得继续生成看似完整的分析结果。

## 调整后的模型链路

```text
用户输入
  → 信息采集：意图识别、字段提取、上下文合并
  → 分支判断
      → scope_guidance：能力范围说明
      → need_input：已知信息复述与渐进式追问
      → normal：确定性决策核心
      → follow_up：解释或局部重算
      → safety_boundary：安全边界回复
      → invalid_input：字段修正提示
  → 自适应结果表达
  → 结束
```

平台现有五个节点可以继续承载上述责任。优先通过扩展信息采集节点输出和结果输出节点分支实现，不为每一种意图新增独立大模型节点。若星辰平台的节点分支能力无法稳定执行，再评估增加条件节点。

## 节点契约

信息采集节点至少向后传递以下数据：

```json
{
  "flow_mode": "scope_guidance | need_input | normal | follow_up | safety_boundary | invalid_input",
  "user_intent_summary": "只复述用户明确表达的目标",
  "known_fields": {},
  "missing_fields": [],
  "changed_fields": [],
  "scenario_overrides": {},
  "previous_result": null,
  "follow_up_question": null,
  "validation_errors": []
}
```

字段值只允许来自用户当前输入、同一会话中已经确认的字段或确定性核心输出。`changed_fields` 记录本轮明确更正或假设涉及的字段名；`scenario_overrides` 只保存用户明确提出的假设值；`previous_result` 只允许引用同一会话中已有的确定性结果或用户重新粘贴的决策卡。大模型不得推测收入、可支配资金、日均花销、价格、使用频率和替代方案金额。

结果输出节点只执行与 `flow_mode` 对应的一种回复结构，不混合其他分支。确定性核心的安全校验可以处理所有输入；财务计算只在 `normal` 或需要局部重算的 `follow_up` 中执行。`safety_boundary` 和 `invalid_input` 必须在财务计算前停止。

## 会话与持久化边界

本设计要求同一对话内保留已经确认的字段。实施前需要在讯飞星辰平台验证信息采集节点能否接收历史消息或保存会话变量。

平台支持会话内上下文时，使用会话变量合并新旧字段。明确更正写回 `known_fields`，其他已确认字段保持不变；假设值只进入 `scenario_overrides`，完成本轮比较后不写回原方案。

平台无法稳定保留会话变量时，结果中继续生成可复制决策卡。用户发起新对话或复盘时，需要粘贴决策卡或重新提供关键字段。页面和回复不得承诺跨会话自动记忆。

## 错误处理

1. 意图不明确时，询问用户希望了解整体资金安排，还是分析一笔具体消费。
2. 金额单位不明确时，只确认单位，不进入计算。
3. 新输入与已确认字段冲突时，复述新旧值并请用户确认。
4. 确定性核心返回错误时，输出错误节点和需要修正的字段，不继续生成灯号。
5. 输出节点缺少确定性结果时，不自行心算或补写结果。
6. 用户连续偏离产品范围时，保持简短说明，并停止重复索要消费字段。

## 测试设计

### 新增场景

1. 一般理财问题：“我应该怎么理财？”预期进入 `scope_guidance`，不输出灯号，不集中追问五个字段。
2. 名称误解：“我想实现财富自由，你能教我投资吗？”预期说明边界，引导到具体消费，不提供投资建议。
3. 极简消费输入：“我想买电脑。”预期先询问价格和可支配资金，最多两个问题。
4. 分轮补充：用户分三轮提供价格、资金、日均花销和记账天数。预期保留已知字段，不重复提问。
5. 结果解释：“黄灯是什么意思？”预期只解释现金安全垫含义，不重复决策卡。
6. 局部重算：“如果预算降到 5000 元呢？”预期将 5000 元写入 `scenario_overrides.price`，沿用其他已确认字段，重新计算受影响结果并展示差异，原方案价格保持不变。
7. 上下文不足的追问：新对话直接问“如果改成 5000 呢？”预期要求说明购买内容和原始关键字段，不猜测上下文。
8. 字段更正：用户先说价格 6999 元，后说“价格其实是 5999 元”。预期采用明确更正的新价格，并只覆盖价格字段。
9. 单位歧义：“预算 5k。”平台无法稳定解析时，预期确认是否为 5000 元。
10. 用户主动要求完整报告。预期重新输出完整决策卡。

### 回归场景

继续执行现有完整输入、财务红灯、安全边界、证据已齐和六项本地公式测试。新增分流不得改变既有公式结果、灯号优先级、决策状态含义和隐私边界。

现有缺失输入用例原本允许一次询问三个问题。本设计将交互上限调整为每轮两个问题，因此该用例需要更新预期后重新运行，不能把旧结果直接当作新版通过证据。

### 用户验收

至少让包括本次反馈者在内的三位目标用户完成一次脱敏测试。每位用户先自由输入，不提前发送字段模板，再检查：

1. 是否能说清作品主要用途。
2. 是否知道下一步需要提供什么。
3. 是否出现答非所问或重复追问。
4. 是否能区分财务灯号和购买价值判断。
5. 是否愿意执行给出的当天行动。

## 实施顺序与影响范围

1. 先从讯飞星辰平台核对并记录当前工作流的提示词、代码、变量映射、会话能力和发布状态。
2. 在项目文件中更新页面文案、信息采集提示词、结果输出提示词和测试预期。
3. 在讯飞星辰平台复制当前工作流或保存可回退版本，再修改配置。
4. 先运行新增分流测试，再运行现有回归测试。
5. 所有测试通过后更新正式发布版本和项目记录。

实际修改平台前需要再次确认当前工作流编号、发布状态、会话变量能力和回退方式。平台修改可能影响公开体验，保存或发布前应保留当前配置截图和测试记录。

## 完成标志

1. 页面简介、欢迎语和开场问题与本设计一致。
2. 六种 `flow_mode` 均有唯一、可识别的输出行为。
3. 一般理财、分轮补充、结果追问和局部重算测试通过。
4. 现有公式、完整输入、财务红灯、安全边界和证据已齐回归测试继续通过，缺失输入用例按新版预期通过。
5. 三位目标用户能够理解用途，且测试记录中没有未解释的答非所问。
6. 当前提示词、工作流配置、测试记录和对外介绍使用同一版本口径。
